# Лабораторная работа №3 — асинхронная обработка через RabbitMQ

Решение PA3 на базе PA2. Предыдущие работы в `lb1` и `lb2` не изменены.
Вычисление rank полностью вынесено из веб-приложения в отдельный .NET-процесс
**RankCalculator**. Несколько процессов читают одну очередь как конкурирующие
потребители. В сообщении передаётся только GUID текста, сам текст хранится в Redis.

## Запуск

Нужен Docker Desktop с Linux containers и Docker Compose v2. Порты 5001, 5002,
8080 и 15672 должны быть свободны. Перед запуском остановить стенд PA2:
`..\lb2\scripts\stop.ps1`. Команды далее выполнять из `lb3`.

```powershell
.\scripts\start.ps1 -Workers 2
```

- Приложение: http://localhost:8080/.
- Прямой доступ к Valuator: http://localhost:5001/ и http://localhost:5002/.
- Панель RabbitMQ: http://localhost:15672/, учебные логин/пароль:
  `valuator` / `valuator-local` (опубликована только на localhost).
- Общая очередь: `valuator.processing.rank`.
- Очередь некорректных сообщений: `valuator.processing.rank.failed`.

```powershell
# Четыре конкурирующих обработчика
.\scripts\start.ps1 -Workers 4

# Задержка для наглядной демонстрации асинхронности (по умолчанию 0)
.\scripts\start.ps1 -Workers 2 -ProcessingDelayMs 2000

# Сохраняются возможности PA2
.\scripts\start.ps1 -Workers 2 -Method least_conn -ThirdInstance

# Остановка всей системы с сохранением данных и сообщений
.\scripts\stop.ps1
```

Redis, RabbitMQ и общие ключи форм используют отдельные постоянные volumes
проекта `rp-lb3`. После `stop.ps1` данные не удаляются. Скрипт запуска сначала
ожидает готовности Redis и RabbitMQ, затем запускает работников и веб-экземпляры.
Имя и группу для страницы About заполнить в `Valuator/appsettings.json`.

## Что изменилось по сравнению с PA2

1. `Index.OnPostAsync` сохраняет текст и similarity, создаёт задание и отправляет
   его ID в RabbitMQ; вычисления rank здесь нет. После этого возвращает 302 на summary.
2. `RankCalculator` получает ID, читает текст из Redis, вычисляет долю неалфавитных
   символов и сохраняет `RANK-{id}`. Для демонстрации также сохраняется `WORKER-{id}`.
3. `Summary` различает неизвестный ID (404), существующую незавершённую оценку и
   готовый результат. До готовности отображает точную фразу
   **«Оценка содержания не завершена»**, обновляясь через две секунды.
4. Nginx, общий Redis и общие ключи защиты форм работают как в PA2.

## Надёжность доставки

- Одна durable-очередь на всех работников; `autoAck=false`, `prefetch=1`.
  Задания распределяются между свободными потребителями, а не рассылаются всем.
- Сообщения persistent, публикация ожидает publisher confirmation. Результат
  подтверждается работником только после записи в Redis.
- При аварии работника до ack RabbitMQ может передать сообщение другому процессу.
- Повторная доставка допустима (at-least-once). Lua-скрипт записывает результат
  только один раз, сохраняя имя первого завершившего работника.
- Redis outbox хранит ID ещё не подтверждённых публикаций. Текст, similarity и
  outbox сохраняются одним Lua-скриптом. При недоступности брокера POST ожидает
  не более пяти секунд попытку отправки, затем перенаправляет на pending summary;
  фоновый отправитель повторяет публикацию каждые две секунды. Этот таймаут
  относится к отправке в брокер; операции Redis имеют свои таймауты клиента.
- Несколько веб-экземпляров могут повторно опубликовать один ID: это безопасно
  благодаря идемпотентному сохранению rank. Outbox удаляется только после confirm.
- При недоступном Redis работник возвращает сообщение в очередь с задержкой.
- Неверный ID или отсутствующий текст направляются в failed-очередь без бесконечного
  повторения. После потери соединения работник переподключается.

В этом учебном стенде Redis и RabbitMQ одиночные: их репликация не реализована.
Сохранение на диске и повторы не означают гарантию отсутствия потерь при любом
аппаратном сбое. Общее хранилище ключей форм — Docker volume для локального стенда.

## Проверки и демонстрация

```powershell
# Сборка и модульные тесты (.NET SDK 8)
dotnet test ds-2024.sln -c Release

# Реальный стенд: pending → готовый rank, несколько работников, отказ web-экземпляра
.\scripts\start.ps1 -Workers 2 -ProcessingDelayMs 250
.\scripts\test.ps1 -TestAsync -TestFailover
```

Тест временно останавливает всех работников, отправляет текст и проверяет pending.
После запуска работников ожидает готовый результат. Затем отправляет 16 текстов
и проверяет, что результаты обработаны как минимум двумя разными процессами.
Также проверяются rank, similarity, общие antiforgery-токены, чтение результатов
на разных веб-экземплярах и доступность после остановки app1.
Тестовые тексты с уникальными ID остаются в учебной базе.

Для наблюдения вручную:

```powershell
docker compose stop rankcalculator
# Отправить текст: summary показывает незавершённую оценку
docker compose start rankcalculator
# Summary автоматически покажет результат
docker compose logs --tail 100 rankcalculator
docker compose exec rabbitmq rabbitmqctl list_queues name messages_ready messages_unacknowledged consumers
```

Для эксперимента с аварией во время обработки использовать задержку 10000 мс,
отправить несколько текстов, выбрать один контейнер из `docker compose ps` и
остановить его командой `docker kill <имя-контейнера>`. Другой работник должен
получить неподтверждённое задание. После эксперимента выполнить `start.ps1`.

Для проверки outbox остановить RabbitMQ (`docker compose stop rabbitmq`), отправить
текст, затем вернуть брокер (`docker compose start rabbitmq`): оценка должна
завершиться после переподключения и повторной публикации.

Модульные тесты: подсчёт rank, валидация ID сообщения и общие ключи форм.
Redis-интеграционный тест запускается при заданной переменной `VALUATOR_TEST_REDIS`
для отдельно доступного Redis; без неё явно пропускается.

GitHub Actions: `.github/workflows/lb3.yml` собирает решение, запускает настоящий
Docker-стенд и выполняет асинхронный сценарий. Локально Docker отсутствует,
поэтому результаты контейнерного прогона следует смотреть в Actions или запускать
самостоятельно; наличие сценария не означает успешного выполнения стенда.

## Структура

- `Valuator` — веб-приложение и отправитель сообщений с повторной публикацией outbox.
- `RankCalculator` — отдельный фоновый процесс; только здесь находится TextEvaluator.
- `Valuator.Shared` — доступ к Redis, описание очереди и формат сообщения.
- `Valuator.Tests` — тесты из PA1/PA2 и новые проверки для PA3.
- `compose.yaml`, Dockerfile — образы и запуск всех компонентов.
- `scripts` — запуск, остановка и проверка.
