# Лабораторная работа №6 — Сегментирование базы данных

Реализация [PA6](https://github.com/tanyginvv/DISTRIBUTED-PROGRAMMING/tree/pa6)
на основе PA4, как требует условие. Предыдущие лабораторные сохранены отдельно.

## Что реализовано

В форме есть список «Страна гражданства». Сервер проверяет выбранное значение
и определяет ShardKey по таблице:

| Страна | Регион | Переменная | Сервис Compose | Порт localhost |
| --- | --- | --- | --- | --- |
| Russia | RU | DB_RU | redis-ru | 6001 |
| France | EU | DB_EU | redis-eu | 6002 |
| Germany | EU | DB_EU | redis-eu | 6002 |
| UAE | ASIA | DB_ASIA | redis-asia | 6003 |
| India | ASIA | DB_ASIA | redis-asia | 6003 |

Четвёртый Redis — `redis-main` (`DB_MAIN`, порт 6000) — хранит **только** строки
`ID текста → RU/EU/ASIA`. Это Shard Map. Все четыре сервера независимы:
Redis Cluster, репликация и общие volumes между ними не используются.

В региональном Redis находятся текст, страна, регион, similarity, rank, имя
обработчика, набор текстов для поиска дубликатов и outbox заданий/событий.
Дубликаты определяются **внутри региона**: France и Germany используют общий
набор EU, а тот же текст в Russia считается новым для RU.

При каждой операции по ID `ShardConnections.FindAsync` читает карту и выводит:

```text
LOOKUP: 9b2fa05d-c54d-427f-b443-2b912d96aaa6, RU
```

Это относится к Valuator, RankCalculator и их отправителям outbox.
EventsLogger получает готовые события из RabbitMQ и не обращается к Redis.
Неизвестный ID даёт `LOOKUP: ..., NOT_FOUND`; Summary возвращает HTTP 404.

## Запуск

Нужны Docker с Linux-контейнерами, Compose v2 и PowerShell. Для локальной сборки
нужен .NET SDK 8. Сначала остановите стенд другой лабораторной: порты веб-приложения
и RabbitMQ совпадают. Из папки `lb6`:

```powershell
./scripts/start.ps1 -Workers 2
```

Откройте http://localhost:8080/, выберите страну и отправьте текст. Summary
показывает оценки, страну и регион. Незавершённая оценка ожидается с обновлением
страницы, как в PA4. SignalR из PA5 в этой лабораторной не требуется.

Веб-экземпляры: http://localhost:5001/ и http://localhost:5002/.
Панель RabbitMQ: http://localhost:15672/, `valuator` / `valuator-local`.
Опубликованные порты привязаны к localhost.

```powershell
docker compose logs -f app1 app2 rankcalculator
docker compose logs -f eventslogger1 eventslogger2
./scripts/stop.ps1
```

Остановка сохраняет данные. Volumes проекта `rp-lb6` отделены от предыдущих работ.
Имя и группу для About можно заполнить в `Valuator/appsettings.json`.

## Настройка подключений

При запуске процессов вне Docker задайте переменные в каждом процессе Valuator
и RankCalculator; эти значения также используются по умолчанию:

```text
DB_MAIN=localhost:6000
DB_RU=localhost:6001
DB_EU=localhost:6002
DB_ASIA=localhost:6003
```

В Compose те же переменные ссылаются на DNS-имена четырёх сервисов, порт 6379.
Работник получает из очереди **только ID**, сам делает LOOKUP и читает нужный сегмент.
Два независимых EventsLogger получают оба типа событий через fanout RabbitMQ.

## Проверки

```powershell
dotnet test ds-2024.sln -c Release
./scripts/start.ps1 -Workers 2 -ProcessingDelayMs 250
./scripts/test.ps1 -TestShards -TestAsync -TestEvents -TestFailover
```

Проверяется отправка текста для всех пяти стран через разные веб-экземпляры,
содержимое MAIN, отсутствие текста и оценок в чужих сегментах, региональные
дубликаты, LOOKUP в веб-приложениях и работниках, два подписчика, восстановление
подписчика и отказ одного веб-экземпляра.

Интеграционный .NET-тест включается переменной `VALUATOR_TEST_SHARDS=1`.
Запускайте его против выделенных тестовых Redis **до запуска приложений и
работников**, чтобы фоновая обработка не забирала тестовые outbox-записи.
Поднять только Redis: `docker compose up -d --wait redis-main redis-ru redis-eu redis-asia`.
После теста уберите переменную из окружения.

Тест дополнительно проверяет конкурентное сохранение дубликатов, идемпотентное
завершение заданий, размещение outbox и неизвестные ID. Без переменной он явно
пропускается. Полный прогон выполняет `.github/workflows/lb6.yml` в GitHub Actions.

## Порядок записи и ограничения

Сначала создаётся запись карты, затем один Lua-скрипт в выбранном сегменте
сохраняет текст, similarity и outbox. Поэтому доступное работнику задание уже
имеет маршрут. Между независимыми Redis нет общей транзакции: сбой до записи
сегмента может оставить неиспользуемую запись карты; Summary для неё возвращает
404. При неопределённом результате сетевого сбоя не выполняется удаление карты,
которое могло бы оставить уже сохранённый текст без маршрута.

Outbox удаляется после подтверждения RabbitMQ. Доставка at-least-once допускает
повторы; сохранённый rank не перезаписывается при повторной обработке.
MAIN и отдельные Redis не имеют резервных реплик. Это пример сегментирования,
а не автоматического восстановления БД или переноса данных между регионами.
